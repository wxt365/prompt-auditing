# 双协议与 Windows 桌面模式

本轮需求将支持范围扩展为 Responses、Chat Completions 和 Windows 浏览器管理页。旧 MVP 文档及验收矩阵中的历史结果不能证明新增功能已经验证通过。

## 协议

2026-10-28：`trial-20261028.3` 以统一 JSON 扩展检查替代逐字段白名单拒绝。两种接口在各层接受普通扩展 JSON，递归检测键名与字符串值，保留原字段；未知 JSON 类型也检查后交给上游。已知字段仍校验类型，扩展协议字段默认不可替换，附件限制保持。详见 [JSON 扩展兼容](json-extensions-20261028.md)。下述 `.2` 为历史修复记录，未知字段拒绝策略已被本次取代。

2026-10-28：`trial-20261028.2` 补充 Responses 历史 `output_text.logprobs` 登记，支持 null、空数组和固定的 `token/logprob/top_logprobs` 概率数组，修复此字段在本地被误拒绝为 422 的问题。字段保留转发，token 文本继续参与审计，未知字段仍拒绝。复现与验证见 [logprobs 兼容修复](responses-logprobs-20261028.md)。

两条路由分别解析，保持原接口转发，不进行协议转换：

| 接口 | 检测范围 |
| --- | --- |
| `POST /v1/responses` | 现有 instructions、input、工具及参数 Schema 等文本 |
| `POST /v1/chat/completions` | messages 文本、工具输出、工具调用参数、function 工具定义、参数及结构化输出 Schema，以及已登记协议字符串 |

两个接口共用认证、限流、gzip 检测、先替换后检查、非级联脱敏、事务审计和 SSE 转发。先在原文上计算一次替换，再对替换结果检查阻断、告警和放行规则；替换后仍命中阻断规则才拒绝。替换成功并通过检查时记录 `mask`，已被替换消除的内容不再记录为阻断命中。重叠替换取最左、同起点最长、同范围按内部 ID 排序，审计只保留实际选中的替换规则。Chat Completions 支持文本消息、文本内容数组、function 工具及旧 functions/function_call；其图片、音频和文件附件继续拒绝，普通 JSON 扩展检查后保留。Responses 另外支持下述 Codex 图片及工具历史。工具名、角色、模型名、Schema 动态键及引用等不能安全替换的位置，命中 mask 时提升为 block。

Responses 会话中的 `custom_tool_call.input`、`custom_tool_call_output.output` 与普通函数工具内容一样参与审计和脱敏。消息或工具输出的内容数组允许 `input_image`，支持内嵌 PNG/JPEG/WebP/GIF Base64 或 HTTP(S) 图片 URL；图片数据不参与文本匹配，保持原样转发，网关不抓取图片或识别图片文字。其他附件仍拒绝，普通扩展字段递归检查后保留。载荷不兼容时，422 响应及管理页“运行状态”会显示具体原因和字段路径，并移除当前请求的凭证。

Responses 的 `input` 消息支持省略 `type` 的简写，例如 `{"role":"user","content":"hello"}`。省略时必须具有 `system`、`developer`、`user` 或 `assistant` 角色以及非空值的 `content`，内容可为字符串或已支持的内容数组；仍校验已知字段类型，不接受未支持附件，普通扩展字段经过检查后保留。此兼容不会给转发正文补写 `type`，正文继续参与替换和拦截。显式填写无效 `type`（例如 `null`、数字或空字符串）仍拒绝；新增的非附件 JSON 类型递归检查后交给上游验证。

`responses-message-20261027` 修复了省略消息 `type` 时被本地误拒绝的问题。回归先在旧逻辑中复现 `/input/0/type 必须是字符串`，再验证简写消息的字符串及数组内容、四种角色、原文转发、认证保留、SSE 返回、先替换后检查、阻断审计及非法结构拒绝。检查使用本地模拟上游，尚未验证用户 Harness 的完整请求及其真实上游服务；官方在线文档在当前环境无法访问。

桌面端另支持 `reasoning.context`、`additional_tools` 历史项及递归 `namespace` 工具定义、函数调用的命名空间、消息阶段和推理文本。嵌套工具说明及 Schema 描述参与脱敏，工具名、动态参数名及语法定义继续按不可脱敏文本审计。

上游填写 API 基础地址，例如 `https://api.example.com/v1`；代理按请求路由附加 `/responses` 或 `/chat/completions`。仍使用固定上游，不接受客户端指定转发目标。

## 可视化配置

管理页使用 Go embed 内嵌 HTML、CSS 和 JavaScript，无 Node.js、Python 或额外桌面框架依赖。

- 连接设置：本地监听端口、固定上游、认证方式、大小限制、并发限制和审计保留参数。只需填写 1 至 65535 的整数端口，默认 `18080`；默认回环地址为 `127.0.0.1`，已有 IPv6 或其他回环地址会保留，不需要重新填写。
- 首次配置：新设置库标记为待配置，页面上游输入框为空；保存有效连接设置前不启动代理，再次启动仍打开配置页。保存成功后清除标记并启动代理；旧设置没有该标记，保持原启动行为。顶部“本地代理运行中”只代表本地服务与审计正常，不代表上游可用。
- 手动连接检查：检查输入框当前地址，不保存设置、不重启代理。`POST /api/check-upstream` 沿用管理会话与来源校验，复用代理的 TLS 和环境代理设置，在 5 秒内发送不带认证或正文的 `HEAD <上游地址>/models`，不读取正文、不跟随重定向、不调用模型。收到任意 HTTP 状态均显示可达及具体状态，明确未验证密钥、模型或完整请求；连接失败显示固定分类，不返回原始网络错误。检查不持有控制器互斥锁，修改地址会清除旧结果，并丢弃在途旧地址检查结果。
- 安全规则：表格和表单编辑关键字、映射、正则及私网 IPv4 规则；填写中文规则名称，内部 ID 自动生成，改名不改变 ID；完整规则集及版本在同一事务中保存。
- 审计日志：默认查询阻断 / 拒绝，按动作、请求 ID、规则名称和本机时间筛选；每页 50 条，可查看命中规则及处理结果。
- 实时日志：开关控制调试采集，每秒更新请求阶段、本地及上游 HTTP 状态、耗时、错误原因与命中规则名称，支持筛选和仅异常。
- 运行状态：代理与审计状态、当前规则版本、数据目录、启动和停止操作。
- 保存连接设置会重启代理；运行时保存规则会重启代理，停止中的代理不会因保存规则而启动。
- 保存和启停串行执行，状态和查询仅短暂读取内存快照，不持锁等待代理停止。页面显示正在保存、重启或停止；等待期间仍可切换页面、查询审计并查看实时日志自动刷新，保存与启停按钮暂时禁用。规则保存仍会重启代理，尚未采用热切换。

首次运行在 `%APPDATA%\CodexSecurityGateway` 自动创建：

| 文件 | 用途 |
| --- | --- |
| `settings.db` | 普通连接设置、Windows DPAPI 加密后的凭证 |
| `policy.db` | 安全规则 |
| `audit.db` | 审计事件及明细 |

新模式不读取 YAML、不修改原 CLI 数据目录。现有数据库缺失或校验失败时拒绝启动，不会静默覆盖或重建安全规则。

管理服务监听独立的随机回环端口，与模型接口分离。每次运行生成独立管理会话令牌，通过浏览器 URL fragment 交给页面，随后从地址栏移除；API 使用 Bearer 认证，并检查 Host 和 Origin，拒绝跨站和域名重绑定访问。页面不使用外部资源，返回禁止缓存与 CSP 等 Header。上游密钥不通过读取设置接口返回，本地令牌仅通过显式复制操作读取。

管理 API 的请求体读取、数据库查询和响应写入不持有控制器状态锁。独立操作锁串行化设置保存、规则保存和启停，避免配置与活动代理交错；退出标记会在排队操作开始前再次检查。源码分别位于 `desktop.go`（入口与初始化）、`desktop_lifecycle.go`（状态与资源启停）、`desktop_api.go`（管理认证与 API）。2026-10-27 全量测试与带全部验证标签的 vet 通过；临时数据库及受控本机上游验证四类启停/保存期间五类查询可返回、并发保存顺序、退出拒绝排队重启、慢响应不阻塞启停、无效保存保留原实例、在途请求完成及规则版本一致，重复生命周期回归 20 次通过。Chrome 以模拟管理 API 验证等待期间导航、审计查询、实时刷新和 390px 布局，截图 `dist/desktop-preview/lifecycle-*.png`；`internal/app` 的 Linux/macOS 交叉编译通过。未执行 race 或完整桌面 EXE 托盘验证，本机配置和运行实例未改动，该阶段完成后已构建 r3 试用包，见下文。

新安装默认使用 `18080`。已保存的端口（包括旧版 `8080`）继续沿用，不自动覆盖；如需切换，在界面修改并同步更新客户端 API 地址。代理端口按设置保存并在下次启动继续使用；Web 管理端口通过 `127.0.0.1:0` 交给系统分配，本次运行期间不变，下次启动可能变化，也可能复用原来的空闲端口。客户端 API 地址必须使用代理端口，管理页从托盘打开即可。代理端口被占用或被系统限制时代理启动失败，托盘和管理页仍可用，页面显示原因；不会自动改用其他代理端口，以免客户端地址失效。保存时若端口与当前 Web 管理端口相同，前端和后端会提前拒绝，不改变现有设置或停止运行中的代理。其他服务占用代理端口时，保存设置后的代理重启可能失败，需要在管理页改用空闲端口，并同步修改客户端地址。

## 查询拦截原因

从托盘打开管理页，进入“审计日志”。默认显示本地阻断和系统拒绝记录；点击“查询 / 刷新”更新列表，点击记录的“查看详情”以弹窗查看原因，支持关闭按钮和 Esc，关闭后保留列表位置。请求 ID 可从响应头 `x-gateway-request-id` 获取并按完整值精确筛选，规则名称按包含关系筛选。API 仍兼容 `rule_id` 精确筛选。

详情显示请求时间、处置动作、处理结果、命中次数、规则版本、上游状态码、耗时和错误代码，以及命中的规则名称、规则类型和关键字。命中名称取自请求发生时保存的快照，修改或删除当前规则不会改变历史命中。正则和私网 IPv4 规则保存规则标识、名称和类型，不保存原始命中文本。列表和普通详情不携带请求正文；规则阻断记录可点击“展开请求内容”，通过独立的 `GET /api/audits/{id}/request` 按需读取审计库中已保存、已脱敏的原始 JSON，无需迁移数据库。历史记录没有正文时显示说明；系统拒绝和非阻断记录不提供请求内容。

请求内容按文本安全显示，不执行其中的 HTML；命中关键字按字面值高亮，重复出现的位置也会标记。高亮表示已保存命中词在原始 JSON 中的出现位置，可能包含替换命中，不等同于每个位置均触发阻断。正则、私网 IPv4 规则没有保存命中文本时不高亮；先替换后拦截产生的命中词可能不在原文中，页面会提示结合规则明细查看。预览最多 30 万字符，最多高亮前 200 个命中词、2000 处位置；超过时有明确提示，可通过“下载完整 JSON”获取审计库中保存的完整内容。格式化保留数字精度，下载保留保存的原始 JSON；查询或关闭详情会释放前一条记录的正文和下载链接。

认证失败、载荷不支持或请求超限等属于系统拒绝，详情显示对应错误原因，不会将其标记为内容规则命中。同一请求的决策和完成事件合并为一行；通过本地检查的请求，可切换动作筛选查看转发结果及上游状态码。

查询使用只读连接，不执行日志清理；代理停止后管理页仍可查询。新版启动时自动将 `policy.db` 和 `audit.db` 从版本 1 或 2 升级到版本 3，保留现有规则和审计记录。默认规则补充中文名称，自定义旧规则以原 ID 作为初始名称，可在界面修改；旧审计缺少名称快照时显示原 ID，不补写当前名称。版本 3 保存每条命中的动作和阻断原因；详情顶部汇总真正导致阻断的规则，阻断行置顶标红，区分替换预检和仅告警。旧记录没有逐条动作，页面明确提示无法可靠还原，需要新版重新测试。升级前先退出旧实例并备份整个数据目录；旧版程序不支持直接打开新版数据库，回退需恢复升级前备份。超出保留天数或容量上限的记录仍按既有策略删除；审计服务自身不可用时拒绝的请求可能无法落库，应同时查看“运行状态”。

审计查询的管理会话认证和来源限制与其他管理 API 相同，不通过模型请求端口开放。

## 实时排查请求

进入“实时日志”点击“开启采集”，之后进入网关的请求即会出现。普通 JSON 和 SSE、放行、脱敏、规则阻断及系统拒绝均覆盖；请求进入、读取请求、内容检查、等待上游、接收响应和完成等阶段就地更新，不必等待请求结束。上游响应头到达后显示上游状态码、响应头耗时以及是否为 SSE。HTTP 200 后发生响应流中断时仍显示失败；上游返回 4xx / 5xx 时也显示失败，并保留实际状态码。

“筛选”支持请求 ID、接口、规则名称、内部 ID 和错误代码的包含匹配；“仅异常”显示本地或上游失败、客户端中断和审计写入失败。完整命中明细仍在“审计日志”按请求 ID 查询。管理 API 自身不进入实时请求列表；健康检查会进入列表。

采集开关即时生效，无需重启代理。采集默认关闭，关闭浏览器或切换页面后继续采集；设置保存导致代理重启时仍保留采集状态，完全退出程序后记录清空、下次启动默认关闭。内存仅保留最近 500 条请求，超限淘汰最早记录并显示累计淘汰数。“清空实时日志”不会改变采集开关；关闭采集保留已采集记录供查看。在途请求关闭采集后标记为“采集已停止”，清空或重新开启都不会恢复这些请求的跟踪，实际请求仍继续执行。

实时日志独立于 SQLite 审计写入，审计不可用引起的请求拒绝仍可显示。仅采集请求元信息和经过凭证脱敏的诊断，不记录认证头、请求正文和响应正文；未知路径以固定提示显示，避免保留 URL 中误填的密钥。规则名称最多显示前 20 个，诊断文本限制长度。实时查询沿用管理会话认证、来源检查和禁止缓存策略，不通过模型请求端口开放。

## 沿用客户端认证

默认使用“沿用客户端认证”，不要求在网关中配置上游 API Key。本地服务要求客户端发送单个有效格式的 Bearer 认证头，经过内容检查后将该认证头原样转发给固定上游，由上游验证凭证有效性。仅监听回环地址，仍不允许客户端更换转发目标或跟随重定向。

例如网关上游设置为 `http://192.168.137.250:33000/v1`，Codex 原模型提供商的 `base_url` 改为 `http://127.0.0.1:18080/v1`。Codex 继续使用原来的认证配置，网关不读取 `auth.json`。请求中的密钥仅在当前请求中用于转发及审计脱敏，不保存到设置库；错误响应和阻断审计会清除该请求的密钥。不同请求各自保留认证上下文。

管理页面仍使用独立的会话认证。客户端认证模式隐藏“复制本地令牌”，无需让 Codex 改用网关令牌。用户可以切回“由网关配置上游 API Key”保留原有功能；切换为客户端认证并保存会清除之前保存的上游密钥。升级时已有上游密钥的旧配置保持网关认证，无密钥的旧配置使用客户端认证。
