# 文本规范化优化与验证

日期：2026-10-27。对应代码审查中的第一项改进，仅调整 `internal/security/normalize.go`；不涉及规则配置、认证、数据库结构、代理生命周期或发布包。

## 实施范围

- 纯 ASCII 文本的 NFKC 规范化不改变内容，大小写折叠也不改变字节位置。先确认全文为 ASCII，再按需转为小写，直接使用原始偏移，省去逐片段转换及逐字节映射数组。
- Unicode 文本继续按原来的 NFKC 片段计算位置映射，复用大小写折叠输出缓冲区。转换不能完整放入缓冲区时退回原有转换方式，避免截断。
- 按输入长度预分配 Unicode 文本输出缓冲区，减少扩容。

未引入跨请求缓存，也未修改两阶段规则检查。每次规则检查仍根据当前文本计算结果，因此替换后的文本会重新规范化，不会误用原文映射。正则编译、阶段内规范化复用及 Unicode 映射压缩留待后续测量和优化。

## 同条件基准对比

环境：Windows amd64、AMD Ryzen 5 5600G、Go 1.26.5。规则规模为 16 组替换映射、36 个拦截词、两条正则，全部使用独立测试词。单段文本、未命中；每个场景 `-benchtime=3x`。

本次先在未优化的生产代码上补测中英文混合基准，再修改生产代码并复测。ASCII 基准沿用原来的内容和命名；混合文本包含中文、ASCII、全角、折叠展开及组合字符。

| 场景 | 优化前平均耗时 | 优化后平均耗时 | 优化前累计分配/次 | 优化后累计分配/次 | 分配次数：前 → 后 |
| --- | ---: | ---: | ---: | ---: | ---: |
| ASCII 64 KiB | 15.06 ms | 3.18 ms | 36,258,616 B | 27,789 B | 131,254 → 123 |
| ASCII 1 MiB | 235.09 ms | 50.49 ms | 580,944,712 B | 29,765 B | 2,097,355 → 125 |
| ASCII 5 MiB | 1,104.83 ms | 251.59 ms | 2,905,176,834 B | 29,794 B | 10,485,968 → 126 |
| 混合 64 KiB | 16.77 ms | 7.10 ms | 24,696,269 B | 2,266,744 B | 89,262 → 146 |
| 混合 1 MiB | 188.22 ms | 115.24 ms | 398,484,669 B | 35,688,360 B | 1,426,236 → 144 |
| 混合 5 MiB | 954.21 ms | 576.59 ms | 1,992,908,541 B | 178,294,701 B | 7,130,497 → 144 |

1 MiB ASCII 检测约加快 4.66 倍；混合文本耗时降低约 38.8%，累计分配减少约 91.0%。表中是整个规则引擎的检测结果，并非单独规范化函数的耗时。

累计分配表示执行过程中申请的总字节数，包含之后可被回收的对象，**不是常驻内存或峰值内存**。ASCII 样本为小写，因而无需额外分配小写副本；大写 ASCII 需要分配转换后的文本。Unicode 路径仍为规范化字节保存原文映射，因此混合长文本的分配仍随长度增长。

这些是短时本机样本，未测峰值 RSS 和持续承载上限。测试期间没有停止当前用户网关，也未更改本机配置；本机其他进程仍可能影响耗时。最终基准在随机差分测试结束后单独运行，避免测试任务之间争用 CPU。

## HTTP、SSE 与真实审计验证

64 KiB 请求，每次替换一处，启用实时采集和 SQLite `synchronous=FULL` 审计；本机模拟上游立即返回 SSE。每场景 30 次请求。优化前值沿用代码审查阶段保存的测试结果。

| 接口 | 并发数 | 首字节 P95：前 → 后 | 本次批次吞吐：前 → 后 |
| --- | ---: | ---: | ---: |
| Responses | 1 | 39.67 → 6.00 ms | 44.7 → 139.9 请求/秒 |
| Responses | 10 | 85.98 → 28.00 ms | 123.0 → 333.3 请求/秒 |
| Chat Completions | 1 | 60.38 → 6.19 ms | 39.0 → 139.2 请求/秒 |
| Chat Completions | 10 | 104.27 → 32.37 ms | 118.4 → 318.7 请求/秒 |

全部请求及持久化审计核验通过。吞吐为短批次观测值，不是服务容量或真实模型响应速度。原有两条正则及私网检测场景 P95 为 58.70 ms；空规则 SSE 首字节额外延迟 P95 为 1.00 ms，这两项未因本次规范化优化出现明显变化。

## 正确性验证

新增 `internal/security/normalize_test.go`，覆盖 ASCII 大小写、全角字符、折叠展开、组合字符、兼容连字、希腊字符、长 ASCII 前缀后的 Unicode、非法区间及替换结果再次命中阻断规则。检查原文区间端点，确认阻断预演仍保留输入原文。

测试文件保留原算法作为差分参照，逐字节比较规范化文本与原文位置映射。15 秒随机测试执行 235,476 次，未发现差异；随机输入限于不超过 512 字节的有效 UTF-8 字符串。默认测试也会运行固定种子。

以下验证全部通过：

```powershell
go test ./...
go vet -tags codex_contract,native_e2e,performance ./...
go test ./internal/security -run '^$' -fuzz '^FuzzNormalizeWithMapping$' -fuzztime=15s -parallel=2

go test -tags performance ./tests/performance -run '^$' -bench '^Benchmark' -benchtime=3x -count=1 -benchmem
```
