# 上游连接检查提示修正

2026-10-28，版本 `trial-20261028.1`。

用户反馈仅连接检查显示红色 404，客户端调用未报告失败。源码确认该检查使用不带认证和正文的 `HEAD <基础地址>/models`，收到 HTTP 响应即标记可达；旧页面却将所有 HTTP 4xx/5xx 显示为红色，容易被误认为模型接口不可用。

修正页面显示，不改变检查请求或代理转发：

- HTTP 2xx 显示绿色“网络可达”；重定向及 HTTP 4xx/5xx 显示黄色“网络可达”，保留实际状态。
- 404 明确表示检查路径 `/models` 返回未找到，可能未开放该路径，不能据此判断 Responses 或 Chat Completions 不可用。
- 405 说明 HEAD 方法不被接受，401 说明检查未携带认证；403、重定向、5xx 分别说明访问拒绝、未跟随跳转或服务端错误。
- 网络失败或超时仍显示红色。所有 HTTP 可达结果继续说明密钥、模型和完整请求未验证。
- 检查前提示明确列出 `/models` 路径。

验证：全量 Go 测试、全部验证标签的 vet、JavaScript 语法检查通过。Chrome 使用真实页面资源和本地模拟管理 API，验证 200/301/401/403/404/405/500 的颜色与说明、网络失败红色、草稿检查不保存、修改地址清除旧结果、保存后状态及 390px 布局。截图和包校验记录位于 `dist/upstream-check-20261028/`。

发布包：`dist/codex-gateway-windows-x64-20261028-r1.zip`，内含短名 EXE、离线说明和校验文件。ZIP CRC、包内与外部 SHA-256、实际版本、Windows x64 GUI 格式、CGO 禁用及新版页面嵌入均已核对，原 r3 包未改变。

本轮未连接用户真实上游、读取认证文件、更改本机配置、停止当前网关或启动新版 EXE。404 提示修正不能作为真实模型调用验证结果。
