codex-gateway 使用说明

Windows 64 位试用版 · trial-20261028.3 · 2026 年 10 月 28 日

本程序在客户端与模型服务之间提供本地审计代理：检查请求、替换敏感字、阻止违规请求，并通过浏览器管理页查看规则与日志。支持 /v1/responses 和 /v1/chat/completions，保持原协议转发，支持普通 JSON 及 SSE 流式响应。

解压后运行 codex-gateway.exe。不需要安装 Go、Node.js、Python 或额外桌面运行时。需要 Windows x64 系统、浏览器，以及客户端原先可以访问的上游 API 服务和认证凭证。

一、首次使用

  1. 将压缩包解压到固定目录，在资源管理器中双击 codex-gateway.exe。首次启动会打开浏览器管理页，显示“待配置上游”，尚不启动代理；关闭后再次启动仍会提示配置。在 Windows 右下角通知区域显示盾牌图标；如未看到，可展开隐藏图标区域。
  2. 在“连接设置”中保留默认监听端口 18080，或填写其他未占用的端口。仅监听本机。
  3. 将“上游 API 地址”填写为原先客户端使用的 API 基础地址，例如 https://api.example.com/v1。不要填写本程序的本地地址，否则会形成代理循环。
  4. 通常选择“沿用客户端认证”。客户端继续使用原有 API Key，网关无需再填写 Key，也不会读取客户端的认证文件。
  5. 可点击“检查上游连接”检查当前填写的地址，无需先保存。随后点击“保存并应用”，确认顶部显示“本地代理运行中”，再将客户端的 API 基础地址改为 http://127.0.0.1:18080/v1。修改监听端口时，请同步修改客户端地址。
  6. 先发送一条简短普通消息。若收到回复，再用实际工作内容测试。接入问题可按第五节排查。

调用链：客户端 → 本机 codex-gateway → 配置的上游 API 服务。管理页使用启动时自动分配的另一个端口，请从托盘打开；不要把管理页地址填入客户端。

保存设置、应用规则或启停时，顶部会显示正在执行的操作。等待在途请求结束期间，仍可切换到运行状态、审计日志或实时日志查看进展；保存和启停按钮暂时禁用，操作结束后恢复。

连接检查最多等待 5 秒，向填写的上游基础地址追加 /models，发送不带认证或正文的 HEAD 请求，不调用模型、不跟随重定向，也不保存配置或重启代理。收到任何 HTTP 状态（包括 401、404、405、500）仅说明网络与 HTTP 可达；请结合显示的状态判断，密钥、模型与完整请求仍需实际调用验证。“本地代理运行中”也不代表上游可用。已有配置升级后保持原启动方式。

检查结果：HTTP 2xx 显示绿色；收到重定向或 HTTP 4xx/5xx 时显示黄色并解释含义。404 仅表示检查路径 /models 返回未找到，不能据此判断模型请求接口不可用；405 表示该路径不接受 HEAD 方法。只有无法完成网络连接或超时等情况显示红色。认证、模型及协议兼容性仍以客户端实际请求为准。

二、客户端与认证设置

项目设置方式
API 基础地址 / Base URLhttp://127.0.0.1:18080/v1；端口以管理页“客户端接入”显示为准。
模型名称保持上游服务支持的模型名。网关不提供模型、不转换模型名。
Responses客户端选择 Responses，网关转发到上游的 /v1/responses。支持省略消息 type 的 role/content 简写。支持历史 output_text.logprobs、非空引用信息和各层 metadata。两种接口的普通 JSON 扩展字段均递归审计并保留转发，不再要求逐项登记字段名；未知 JSON 类型也参与检查，是否被模型接口接受由上游决定。
Chat Completions客户端选择 Chat Completions，网关转发到上游的 /v1/chat/completions。适用于提供 OpenAI 兼容接口的客户端。
沿用客户端认证（推荐）保留客户端原有 API Key。认证头转发给固定上游，由上游验证；认证头不参与内容规则检测。
由网关配置上游 API Key在管理页填写上游 Key，保存后点击“复制本地令牌”，将令牌作为客户端的认证密钥。上游 Key 由 Windows 系统加密保存，不回显。

Codex 用户：只修改当前实际使用的模型提供商配置中的 base_url，保留已有的模型、wire_api 和认证设置。应用是否需要重启或重新连接，取决于客户端如何加载配置。建议先用独立测试客户端验证，避免影响正在工作的会话。

网关不做 Responses 与 Chat Completions 互转。客户端所选协议也必须被上游支持。上游使用 HTTP 时，请求和认证信息以明文在本机与上游之间传输。

三、安全规则

进入“安全规则”，可以启用、关闭、编辑或新增规则。输入便于理解的规则名称，内部 ID 自动生成；编辑完成后点击“保存并应用规则”。

首次运行的默认规则默认行为
敏感字替换已启用，预置 16 组映射，不区分大小写。
敏感字拦截已启用，预置 36 个关键字，不区分大小写。
API 密钥检测已启用，命中内置密钥正则时阻断。检查的是请求正文中的文本，不检查认证头；并非覆盖所有厂商的密钥格式。
密码检测已启用，对匹配密码赋值格式的请求正文进行阻断。
私网 IPv4 检测默认关闭，需要时可手动启用；启用后仅告警，本身不会阻断请求。升级保留已有开关设置。

处理顺序：先替换，再检查拦截。能替换且替换后不再命中的请求可以放行；替换后仍有违规内容，或者模型名、工具名等不可安全替换的位置命中替换规则，则阻断。替换只执行一次，不级联替换。规则检查也包含支持的历史消息、工具文本等，并非仅检查最新一句话。

Responses 支持已登记的图片和工具历史；图片原样转发，不识别图片内文字。Chat Completions 目前支持文本及登记的工具结构。音频、文件及其他未支持结构可能在本地被拒绝。当前规则检查请求内容，不检查模型响应正文。

四、查看阻断原因与调试日志

审计日志

进入“审计日志”，按请求 ID、规则名称或时间查询，默认显示阻断与拒绝记录。点击“查看详情”打开弹窗：

  • 顶部直接列出阻断规则；表格将阻断规则置顶，并以红色背景显示。
  • 导致阻断 表示该命中参与了阻断。如说明为“此位置不可安全替换，转为阻断”，则原本的替换规则因位置限制而拒绝请求。
  • 替换预检 表示该命中可替换，但整个请求因其他原因被阻断，未发往上游；通过检查的请求则显示“执行替换”。
  • 仅告警 不会单独导致阻断。未记录 表示旧日志未保存逐条动作，无法可靠还原具体阻断规则，需重新发起测试。
  • 规则阻断记录可点击“展开请求内容”，查看已保存的原始请求及关键字高亮，并下载完整 JSON。当前请求的认证凭证已脱敏；正则和私网 IPv4 命中不保存原始匹配文本，不会高亮。

多条阻断规则可以同时命中，网关会列出全部已记录的阻断规则。只显示请求最终“阻断”并不表示其他告警或替换规则也在阻止请求。

实时日志

进入“实时日志”并开启采集，然后复现问题。页面显示请求接口、阶段、本地 HTTP、上游 HTTP、耗时及错误代码，每秒刷新，内存最多保留 500 条。重启程序后默认关闭；不记录完整请求和响应正文。

现象判断方法
本地拒绝，上游状态为“—”请求未发送上游。规则阻断通常为 403；非法 JSON、已知字段类型错误或未支持附件通常为 422。查看审计详情或错误代码。
上游返回 401 / 403检查客户端认证、网关认证方式以及上游权限。
上游返回 404 / 422核对上游地址、协议、模型名及上游支持的请求字段，结合错误信息判断。
客户端已断开表示客户端请求上下文已取消，可能是停止、重试或客户端超时；不能仅据此断定用户主动关闭。
HTTP 200 但回复不完整200 可能只代表流式响应头已返回；还需查看请求最终阶段是否完成、是否发生响应流中断。

五、常见问题

程序没有窗口，是不是没启动？

程序以托盘方式运行，不常驻任务栏窗口。单击右下角盾牌图标，或右键选择“打开配置界面”。关闭浏览器页面不会退出代理。需要关闭时，从托盘选择“退出”。同一 Windows 用户只运行一个实例，不支持自动开机启动。

提示端口占用 / 无法监听

从托盘打开管理页，将监听端口改为未占用的端口，例如 38080，保存后同步修改客户端地址。代理端口不能与管理页或其他服务共用；网关不会自动换端口。保存连接设置会重启代理，建议等当前请求结束后操作。

接入后不能回复，如何快速定位？

  1. 若顶部为“待配置上游”，先填写并保存实际上游地址；确认“本地代理运行中”，检查客户端地址与管理页显示一致，且网关进程持续运行。
  2. 使用“检查上游连接”检查网络与 HTTP 可达性；即使检查收到了 HTTP 响应，仍需验证实际认证与模型请求。
  3. 开启实时日志，发送简短消息。没有日志时优先检查客户端连接地址；有日志则根据本地和上游状态区分拒绝位置。
  4. 403 时查看阻断规则及历史消息；422 时查看具体字段路径。向维护者反馈软件版本、请求 ID、时间、协议和错误代码，避免提供真实密钥。
  5. 检查上游是否支持客户端选择的协议。同一网关的 Chat Completions 可用，不代表上游也支持 Responses。

新增字段是否还会出现“未登记”？

普通 JSON 扩展的键名、字符串值和嵌套内容均参与规则检查，通过后保留转发。已知正文仍先替换后检查；扩展协议字段默认不替换，命中替换规则时按“不可安全替换”阻断，避免改坏元数据。合法 Responses 图片保持原样；音频、文件附件、非法 JSON、重复键、过深嵌套和已知字段类型错误仍拒绝。此策略不代表上游支持所有扩展，也不具备编码内容解码、文件扫描或图片文字识别能力。

为什么其他人第一次启动没有我的上游地址？

试用包只包含程序、内置规则与说明。每位用户需要在管理页填写自己的上游地址和认证配置；不会分发原使用者的配置库、密钥或审计日志。

升级、回退与数据位置

设置和日志保存在 %APPDATA%\CodexSecurityGateway，与 EXE 所在目录分离。升级前从托盘退出旧版，备份整个数据目录，再启动新版。新版自动升级规则库和审计库到版本 3，保留已有规则及日志，默认规则只写入新建库；旧记录缺少逐条动作时不会猜测补写。

旧版不能直接打开升级后的数据库。需要回退时，先退出新版，再恢复升级前的整份备份并启动相应旧版。备份数据应妥善保管；审计库中可能保存被阻断请求的原文。卸载只需退出程序后删除解压目录；是否保留数据目录由用户决定。

试用程序尚未进行数字签名。如果 Windows 显示未知发布者，请先确认包的来源并核对校验值；受组织管理的设备按本单位软件使用规定处理。
